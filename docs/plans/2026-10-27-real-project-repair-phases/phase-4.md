# Phase 4 — Native delivery and an independent incident

Parent: [real-project repair](../2026-10-27-real-project-repair.md). Dependency: accepted local phases1–3 and exact integrated candidate. Local packet preparation is part of implementation; external execution/publication needs its actual separate authority.

## Outcome and honest exits

The local exit is a qualified candidate plus one reviewable current-pilot packet. The measured delivery exit is a real repair PR whose exact protected native verification passes. An independent later incident checks generalization. Integration requires a human merge and matching integration proof; it is not performed automatically.

The original CLI case's PR is now merged, so it is a historical regression only. Do not open a duplicate PR against an obsolete failure or count a replay of it as a new organic recovery. A natural current failure may be absent or already claimed; that is no-opportunity/PARTIAL, not permission to inject failures, erase claims or rerun old hosted checks.

## Local preparation

1. Preserve the original-case fixture/provenance and known-good human repair where accessible. Test the production boundary against the failing source, and use the human fix only as a checkable behavioral reference, not an exact-diff requirement. Equivalent correct patches remain acceptable through the same verification gates.
2. Freeze the next-incident selection rule before evaluating results: same owner-authorized pilot scope; an unresolved source assertion; exact retrievable source and complete diagnostic identity; reviewed runtime/profile; full audit fitting a priced and approved envelope; no known unsupported services/credentials; no duplicate of the training incident. Select deterministically by source-event time then immutable incident key. Keep every selected blocked/failed outcome. A changed SHA/attempt is not independent if it is merely the same defect retried.
3. Read current incident/PR/native state before preparing publication. If resolved, use the next eligible ordinary incident. Preserve existing attempt markers and spending records. Prefer a distinct eligible source event. A new execution of an already attempted unresolved source is permitted only through phase3's separately approved, authenticated one-attempt grant and an append-only new execution record; it never resets the old claim or reruns hosted native CI automatically.
4. Reuse `scripts/fleet-native-receipt.mjs`, `scripts/fleet-native-verification.mjs`, publication receipts and `qualifyIncident`. Prepare one pilot's protected `.github/native-policy.json`, exact producer enrollment, workflow/job/matrix obligations, checkout receipts and observation configuration. Do not infer requiredness from whichever jobs passed. A descriptor without deployed producers is not enrolled proof. Do not roll out proof plumbing to 23 repositories before proving this pilot.
5. Include a protected reproduction-profile diff, target Action compatibility, scoped installation/credential availability metadata, the full original audit command, time/operation/cost reservations, provider destinations, original-source availability, expected native checks, cancellation/reconciliation and rollback in the same private packet. No credential values or private source are included in public artifacts.
6. Run final local gates sequentially, review the complete integrated diff, simplify, rebuild/verify bundles and preserve exact input/candidate/check identities. Integrate locally into `develop` under the documented topology. Prepare external actions only after the completed local result is concrete; do not publish a working branch for experimentation.

## Authorized execution, when granted

Use the exact completed candidate and approved packet. Inspect triggers before the single completed integration/consumer publication; avoid Vercel Previews. Monitor each expected check at its exact commit. A new release version is selected by the separate release workflow, not guessed here. Candidate-mode execution may use a fully verified immutable integration commit when explicitly authorized; it must not be labeled a published package release.

Run one authorized repair attempt for the selected current incident. The native failure must reproduce faithfully; a final candidate must pass the unchanged full sandbox audit and all policy/challenge/adjudication gates before ordinary repair-PR publication. Native proposal verification then independently checks exact tested head/merge parents and every enrolled obligation. Keep sandbox fixed, PR-published, native-pending, native-qualified and integrated states separate using the existing evidence contracts.

No automatic paid retry, hosted rerun, fix-and-repush loop, broader credential grant, runner change or merge. On failure, retain the exact logs, process state and costs, repair locally and prepare any necessary new external request. If the actual source is unavailable, provider capacity is exhausted, telemetry is unknown or the approval is absent, finish independent local work and stop dependent execution with its visible next action.

## Acceptance oracles

- **P4-ORIGINAL:** historical reproduction/repair regression passes through the actual production entry path with the complete native failure set and unchanged acceptance commands. It is labeled historical/offline rather than organic delivery.
- **P4-ENROLL:** protected policy and receipt producer identities bind exact source/workflows/jobs/matrix/tested commits. Missing, stale, wrong-repository, skipped, cancelled, pending or partial receipts cannot qualify a proposal.
- **P4-REAL:** one current real incident produces a correct repair PR and all required native checks pass for its exact tested identity. A green wrapper, CaseFile fixed or later unrelated green is insufficient.
- **P4-INDEPENDENT:** selection precedes evaluation; the next incident has a different defect identity and retains complete success/failure/cost evidence. No new incident means generalization unmeasured, not a synthetic substitute.
- **P4-INTEGRATION:** before a human merge, integration remains unmeasured/pending. After an authorized human merge, only exact integration SHA and enrolled target checks can establish integrated recovery. A contradictory authoritative receipt revokes qualification without deleting history.
- **P4-RECOVERY:** absent authority, no opportunity, resolved/claimed incident, failed source/runtime/budget, cancelled provider work, missing native enrollment and corrupt observation each render their state, evidence location and next action. Recovery succeeds through a corrected authorized packet or new eligible event, without hidden state edits.

## Work units and manual gate

Native policy/producer packet and original-case source/ground-truth capture are **[batch-eligible]** read-only/local units with disjoint owned annex files. One owner integrates the packet, source changes and observation wiring; no parallel consumer publication.

The manual gate is the owner's decision on the concrete external packet and any later human merge. The agent prepares/executes authorized operations; the owner is not asked to copy commands or credentials. Approval of this plan alone does not authorize that execution.

## Closeout

Publish only supported aggregate claims through a separately authorized documentation/release/submission action. A reporting/admission fix is not a repaired project; a historical fixture is not a new organic win. Preserve the original 101-attempt denominator and separate candidate/version/window cohorts. If the submission deadline arrives without native delivery proof, keep those effectiveness claims PARTIAL/unmeasured while reporting the completed source fixes accurately.

Handoff includes the accepted source candidate, local gate/review receipts, original/independent incident identities, exact native observations, authorization/spend records, unresolved limitations and rollback. Preserve all evidence outside disposable worktrees, leave `develop` clean with intended work integrated, and prune only owned trees/branches after ancestry and preservation checks. Native/publication authority remains separate from local completion.
