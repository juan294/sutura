# Phase 2 — Focused triage probes

Parent: [Bounded, focused triage](../2026-10-03-sutura-bounded-focused-triage.md).
Depends on phase 1. Owner: Sutura core.

## Change

```
@ focusedTriage(command, failedLog) -> { command, testId, fingerprint } | none
ctx: pure; no IO
pre: command is one line with no `&&`, `||`, `;`, `|`, backticks, `$(` or newline
do:
  1. parse the runner from an allow-listed shape (table below)
  2. parse exactly one failing test id and its failure block from the log
  3. validate the failure is test-level and the file stays in the repository
  4. compute the focused command and the failure fingerprint
br: any step fails -> none (full-command triage, disclosed note)
```

| Runner | Accepted shapes | Dropped | Appended | Failing-test source |
| --- | --- | --- | --- | --- |
| vitest | `[ENV=v ...] [npx\|pnpm exec\|yarn] vitest [run] [flags] [paths]` | `--shard*`, `--coverage*`, `--reporter*`, `--outputFile*`, positional paths | `run <file>` | `FAIL <file> > <name>` (package-qualified by `26e8aa7`) or a GitHub annotation `::error file=<file>,title=<name>…` |
| jest | `[ENV=v ...] [npx\|pnpm exec\|yarn] jest [flags] [paths]` | `--shard*`, `--coverage*`, `--reporters*`, positional paths | `<file>` | `FAIL <file>` with `● <suite> › <name>` |
| node --test | `node [flags] --test [flags] [files]` | positional files | `<file>` | TAP `not ok N - <name>` with `location: '<file>:L:C'` |
| pytest | `[ENV=v ...] [python -m] pytest [flags] [paths]` | `-n*`, `--cov*`, `--junitxml*`, positional paths | `<file>::<name>` | `FAILED <file>::<name>` |

Same-failure check (D4): a focused probe is kept only when (1) it exits
non-zero, (2) the runner parser applied to its output reports a failure of the
same test id, and (3) `errorFingerprint` of that failure block equals the
original's. Collection, import and usage errors never qualify.

```
@ boundedTriage(...) -> TriageVerdict
do:
  1. compute focus when policy.scope = focused
  2. run focused probe 1 alone (attempt 0); keep it only on the same-failure check
  3. continue focused batches under the phase 1 cumulative gate
  4. restart with the full command from attempt 0 at the first focused pass or mismatch
  5. return the verdict and a note naming the focused command or the reason none applied
br: restart -> focused probes discarded from the verdict, kept in the ledger and in spent seconds
```

- The Action and CLI build `{ scope: 'focused', sandboxBudgetSec }`; replay
  keeps the recorded scope.
- `evidence.ts` adds `focused=<kept>/<rejected>`; `score.ts` triage efficiency
  counts focused probes as operations.

`[batch-eligible]` The four runner parsers live in separate modules
(`engine/focus/vitest.ts`, `jest.ts`, `node-test.ts`, `pytest.ts`) with their own
tests; up to two owners write them in parallel; one integration owner writes
`engine/focus/index.ts` and the triage flow.

## Tests (red first)

- Per runner: an accept/reject table including shell operators, package
  scripts, `pnpm -r` runs, compound `… && vitest run` (the benchmark's 7
  compound cases: reject), paths with `..`, two failing files, collection
  errors.
- Real logs: gh-glance `110720064182` (multi-line script: no focus) and cirujano
  `110875289871` (`pnpm -r`: no focus) from the committed fleet fixtures; a
  vitest GitHub-annotation log generated by running vitest 4.1.11 with
  `--reporter=github-actions` on a Placebo JS fixture (real reporter output).
  chapa's sharded command shape is a synthetic case without its content.
- Triage flow with a recorded executor: same failure 4/4 → `real` from focused
  probes; pass at probe 1 and at probe 3 → full restart from attempt 0;
  different test; same test with a different message (fingerprint) → restart;
  restart that exceeds the cumulative budget → `sandbox-budget`.
- Property test: `flaky` and `intermittent` never come from focused probes.
- Placebo regression: for every v0.3.8 benchmark case, focus applies only to the
  single-command `vitest run` cases; every flaky fixture keeps its verdict and
  `reproduced/of` under `SUTURA_TRIAGE_ATTEMPT` numbering (D5).

## Acceptance

Automated: the tests above, full `pnpm run test`, `pnpm run ci:local` on the
integrated commit.

Manual: review the rendered note for one focused, one restarted and one
not-applicable case.
