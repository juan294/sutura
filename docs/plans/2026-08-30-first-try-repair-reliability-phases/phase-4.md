# Phase 4: Dogfood automation — canonical fixture, gate, streak, ledger, canary artifact, evidence id `[batch-eligible]`

## Goal

A dogfood run can only be produced by `scripts/dogfood.mjs`, which refuses
unless every precondition holds on the exact candidate SHA, records every
attempt in an append-only ledger, and feeds a `dogfood` release-evidence id
that requires 10 consecutive `fixed` on one unchanged `packages/` tree.

## Implementation

1. `dogfood.mjs gate [--sha <40hex>]` (default `HEAD`), all via `gh api`
   with injected functions for tests:

   ```js
   // a. exactSha(sha); git status --porcelain must be empty (ignoring docs/demo/thumbnail/);
   //    git rev-parse origin/develop === sha after git fetch
   // b. runs = gh api actions/workflows/ci.yml/runs?head_sha=<sha>&status=completed
   //    require ≥1 with head_branch==='develop' && event==='push' && conclusion==='success'
   // c. canary = latest provider-contract-canary workflow run with head_sha===sha, conclusion success,
   //    artifact 'provider-contract-canary' downloaded (reuse createGitHubEvidenceVerifier),
   //    JSON.headSha===sha, contractVersion===SUPER_REPAIR_PROVIDER_CONTRACT_VERSION (read from
   //    packages/core/dist/index.js), capturedAt within 24 h
   // d. ledger = read docs/demo/dogfood-ledger.json; last = entries.at(-1)
   //    if last && last.outcome !== 'fixed':
   //      require a test whose name includes `live run ${last.suturaRunId}` exists under packages/*/src/**/*.test.ts
   //      and `pnpm --filter @sutura/core --filter @sutura/action test -t "<that name>"` exits 0
   // e. print PASS/FAIL per condition; exit 1 on any FAIL
   ```

2. `dogfood.mjs run --sha <sha> --attempt <n>`:

   ```js
   // a. gate(sha) must pass
   // b. branch = `dogfood/streak-${sha.slice(0,7)}-${n}`; git worktree add <tmp> <sha>
   // c. apply corpus fixture: copy packages/placebo/corpus/repair-dogfood-arithmetic/fixture/packages/core/src/dogfood-add*.ts
   //    into packages/core/src/; commit "test: dogfood streak attempt <n> on <sha7>"
   // d. git push origin <branch>; gh workflow run ci.yml --ref <branch>
   // e. poll gh run list --branch <branch> --workflow ci.yml until completed; require conclusion failure
   //    and that exactly one job step failed with 'pnpm run test'
   // f. poll gh run list --workflow sutura.yml --event workflow_run until the run whose
   //    triggering workflow_run.id === ciRunId completes
   // g. download artifacts: sutura-case-file-<ci>.html, sutura-replay-<ci>.json; store bundle under
   //    packages/action/src/__fixtures__/captured/<ci>/ (uncommitted; Phase 5 commits on gave-up)
   // h. parse outcome from the Sutura job log line /^Sutura outcome: (\S+)$/ and the check-run conclusion
   // i. if fixed: locate PR by head sutura/fix-<ci>; require commit parent === dogfood SHA,
   //    diff touches only packages/core/src/dogfood-add.ts with `-  return left - right;` / `+  return left + right;`;
   //    wait for the PR's CI run to succeed
   // j. append ledger entry {attempt, ciRunId, suturaRunId, dogfoodSha, actionSha: sha,
   //    packagesTreeHash: git rev-parse <sha>:packages, outcome, bundleSha256, sandboxUsd, inferenceUsd,
   //    prUrl?, recordedAt}; recompute resultHash = contentHash(entries); regenerate the .md
   // k. never delete remote branches
   ```

   Cost fields come from the Sutura log lines `Sandbox evidence: … sandbox cost USD=` and
   `Nemotron runtime: … inference cost USD=` (`packages/action/src/evidence.ts:19-38`).

3. `dogfood.mjs streak --sha <sha> --authorize --cap-usd 10`:
   loop `attempt = 1..10`: `run`; stop on outcome ≠ `fixed`; stop when the
   sum of `sandboxUsd + inferenceUsd` over this streak's entries exceeds the
   cap; print the streak length and total cost. `--authorize` is a required
   literal flag so the command cannot be run by accident.

4. Ledger contract: `scripts/dogfood.test.mjs` validates entries with the
   `evidence-contract.mjs` helpers (exact SHAs, nonnegative USD, public run
   URLs), refuses edits that change or remove existing entries (compares the
   prefix of the new file with the committed version via `git show HEAD:…`),
   and checks `resultHash`.

5. Release evidence: `dogfood` check `passed` requires `verifyDogfoodStreak`
   to find ≥10 trailing consecutive `fixed` entries on the release commit's
   `packages/` tree hash; otherwise `pending` with
   `authorizationGate: 'live-dogfood-streak'`.

## Automated success criteria

- `corpus.test.ts` passes with 19 repairables; `placebo` self-check accepts
  the new case (its `repair.diff` turns the fixture green; `break.diff`
  turns it red).
- `dogfood.test.mjs` with injected `gh`/`git`/`fs`: `gate` fails on each of
  the six conditions individually and passes when all hold; `run` appends
  exactly one entry per invocation and refuses to run when `gate` fails;
  `streak` halts at the first non-`fixed` and at the cap; the ledger
  append-only check rejects a mutated earlier entry.
- `provider-contract-canary.test.mjs` asserts the script writes the SHA-bound
  JSON and refuses a dirty tree, and the workflow uploads the artifact.
- `release-evidence.test.mjs`: `dogfood` is `passed` only for a ledger with
  10 trailing `fixed` entries on the matching tree hash; 9 → `pending`; 10
  with one differing tree hash → `pending`.
- `release-workflow.test.mjs` unchanged and green; `test:release-contracts`
  passes with the new files.
- `pnpm run ci:local` passes.
