# Sutura 0.4.0 local release preparation

This is a local candidate procedure, not a publication receipt. Version 0.4.0 was selected for repository assessment, guided adoption and verified recovery. The integration branch is `develop`; production releases come from `main`. No tag, npm publication, hosted activation, paid benchmark, email delivery or newcomer recruitment is authorized by local implementation.

## Candidate and local gates

Freeze the complete source, version metadata and rebuilt `packages/action/dist/index.cjs` in one reviewed local commit before candidate-install verification. Record `git rev-parse HEAD`, the tree identity and command outcomes in the ignored implementation handoff. Required checks are:

```bash
pnpm install --frozen-lockfile
pnpm run build
pnpm run ci:local
pnpm --filter @sutura/core test:coverage
pnpm --filter @sutura/action test:coverage
pnpm run test:ci-routing
node scripts/test-candidate-install.mjs
```

Use the project-pinned package tools. Run checks sequentially and retain failures. The package check exercises the actual packed CLI in an isolated temporary consumer: provider-free assessment, side-effect-free preview, exact-digest local apply, explicit incomplete doctor readiness, version and installed-content identity. It does not establish provider access, activated installation or repair yield. Existing test selection and release-evidence validators retain zero-pass, required-failure and identity refusal behavior; do not replace them with wrapper success.

Independent review covers selected-step identity, assessment read boundaries, setup ownership/resumption, inspect privilege separation, strict outcomes, receipt provenance, outbox retry and privacy, and all-attempt reporting. Reuse unchanged passing evidence; a change invalidates the checks that consume it. Local review findings and their regressions are retained in the private audit and implementation evidence. The unchanged Case Lab continues to display its dated v0.3.9 benchmark; no new live result is inferred.

## Migration

`init` now previews. Review the proposal and use its exact apply command with the same options. Explicitly select credential names; ambient values are ignored. `--force` cannot overwrite customized workflow files. Keep local receipts private. `upgrade` preserves custom jobs, App wiring and permissions and changes only reviewed pins. Pause/resume require a proved disable guard. Removal only deletes an unchanged wholly owned generated workflow and retains credentials and evidence.

Assessment, inspection and doctor share the runtime support contract, but report installed and desired Action identities separately. Missing or older unknown contract evidence stays unknown. A nonzero sandbox exit is insufficient: native and sandbox failure identities must match before repair inference. Operationally successful unsupported/setup stops are not repairs; admitted `require-fixed` remains strict. Unexpected internal/security/evidence failures remain failed monitors.

## Publication and staged installation

Before any separately authorized publication, refresh default/integration refs, branch protection and deployment triggers. The `Publish` workflow runs on a published GitHub release and can publish npm; authorization must cover both effects. Do not push a working branch or create a Preview. Main native checks must pass for the exact publication commit before creating its tag.

Prepare minimal pilot pin changes, protected native-obligation policies, actual checkout receipt producers and exact rollback bytes locally. A policy with no deployed producer remains unenrolled. Native receipts must identify the actual checkout captured before verification in each required job; API `head_sha` is not a substitute. Control jobs without a source checkout need an explicit evidence disposition rather than fabricated tested-source claims.

After authorized pilot activation, observe a 72-hour safety window and at least one organic supported failure with matched reproduction before admitting a stable reliability release. No eligible event means unmeasured. Subsequent waves contain at most three consumers, with the same 72-hour observation boundary. Local preparation does not start those windows.

Rollback is a reviewed restoration of the exact prior Action pin/workflow bytes. It does not delete claims, journals or failed evidence. Hosted failures are diagnosed from existing logs; do not automatically rerun or repush.

## Field and delivery evidence

Begin the 14-day observation window only after the last accepted wave. Keep exact source attempts, unknown/skipped events, cost coverage, native qualification and organic attribution separate. The offline study instructions and instruments are in [the recovery study](../adoption/fleet-recovery-study.md). Synthetic rehearsal is not an independent participant result.

The private weekly queue and email adapter can be prepared without sending. Sending requires an exact reviewed sender, recipient, protected credential reference and fleet-scope binding. Provider acceptance, delivery and owner comprehension are distinct. No email or invitations are part of this local candidate procedure.

Retired guidance: blind workflow replacement through `init --force` and implicit upload of ambient credentials. Historical release, benchmark and failure records remain unchanged.
