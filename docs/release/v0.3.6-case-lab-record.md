## Incident: live recovery evidence refused at publish

- Smoke 1, dispatch `cl-1790923472117-b559752d` (demo run
  [36975022285](https://github.com/juan294/sutura-demo/actions/runs/36975022285)):
  the case materialized (the v0.3.6 fix, now proven live), the controller
  wrote the `await`, and repair PR #53 opened with outcome `fixed`. "Publish
  the public-safe result document" then failed with `Invalid public diagnosis
  recovery evidence`, so nothing was published
- Cause, reproduced locally from the run's replay bundle:
  `packages/case-lab/src/result.ts` bound the recovery grant's
  `baseline.sourceSha` to the displayed demo commit (`a2888b7`). A live grant
  names the materialized case commit instead (`28336b4`, the failing PR head,
  whose parent is `a2888b7`), so no live controller-authorized recovery could
  ever publish. The check dates from `731cb31`; no live run had produced
  recovery evidence before, because live `python-repair` never got past
  materialization
- Fix `bbcb42c`: bind the displayed demo commit to the grant's trusted
  `policyBaseSha`. The regression test uses the real rejected case file
  (`packages/case-lab/src/__fixtures__/live-36975022285-python-repair-fixed-case-file.json`).
  An independent review confirmed the test fails if the binding is removed
- **Limitation:** the new binding is weaker than an exact source binding: any
  child of the demo commit passes. The result schema carries no PR head SHA,
  so an exact binding needs a new identity field
- **Open (not fixed, no live fixture):** the review traced the same mismatch
  in the verification-evidence binding (`caseFile.verification.identity.sourceSha`
  against `identity.demoSha`). It applies only to live runs whose policy
  requires verification; the demo's default policy does not, so it does not
  block the Case Lab today
- The fix is controller-only (the demo checks out `packages/case-lab` at
  `SUTURA_CONTROLLER_SHA`), so no new release was needed. Controller pin
  `1f81a10`; `develop` CI (36976456408) and CodeQL green; `publish-demo`
  again. The site was not redeployed: the browser code imports only types from
  `result.ts` and never runs the validator
