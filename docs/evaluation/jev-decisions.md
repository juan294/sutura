# Local Jev decision evaluation

New semantic repair roles are off by default. Inline calls stop when ordinary controller time is exhausted, preserving reserved verification time. This evaluator validates frozen inputs and reports bounded observations; it never enables a role, changes audit veto policy, dispatches hosted work, or authorizes a paid experiment. Current quality, calibration, speed, repair yield and developer comprehension remain **UNMEASURED**. Offline examples and automated tests are implementation evidence; live API compatibility and quality qualification are separate measurements.

Local heal can explicitly select `--jev-ranking shadow|assist` with `--jev-budget-usd` and the existing key. The [ranking selector](../../packages/core/src/decisions/rank-frontier.ts#L7) sees only the eligible failing frontier. Shadow captures bounded redacted inputs locally and keeps native order, with no inline provider request. Assist may reorder the same IDs within native priority groups; it cannot revive a terminal branch, increase search limits or admit a candidate. Missing, contradictory, uncertain, oversized, unavailable or over-budget evidence retains the native comparator. Public evidence retains baseline/suggested order, policy/model/input identity, resources and fallback; replay uses the recorded controller clock to preserve its latency evidence and exact reports.

`--jev-grounding shadow|assist` post-processes [existing retrieval](../../packages/core/src/decisions/select-grounding.ts#L45), with no additional search or fetch. Code compares explicit package/version facts; semantic relevance/support labels remain judgments. Assist excludes only confidently irrelevant passages with insufficient support, retains contradictions, and keeps all original sources plus exclusion reasons in the report. Uncertainty or conflicting labels preserves the original set; an all-excluded suggestion retains every source with a no-qualified-source warning. The [repair prompt projection](../../packages/core/src/decisions/grounding-prompt.ts#L5) sends selected citations and their labels while keeping excluded source provenance in the case file. Shadow preserves the native prompt and performs no inline inference. Direct grounding callers and URL validation retain their existing behavior. Grounding benefit remains UNMEASURED.

`--jev-classification shadow|assist` uses supplied diagnostic spans and fixed taxonomy classes after baseline reproduction. A usable result preserves the observed command and exact mechanical confidence; ambiguous, missing, conflicting or unavailable answers call the existing classifier within its remaining budget. Shadow captures the actual existing classifier result and makes no inline request. `--jev-recovery shadow|assist` retains the deterministic fast path and changes only the existing generative fallback selection. Supplied alternatives retain controller-owned intents/probes/source hashes; source identity, policy, executed probes and grant derivation still decide authority. Shadow observes an actually validated baseline; assist does not claim to have measured its unexecuted generative counterfactual. These roles do not skip reproduction or final verification. Their benefit remains UNMEASURED.

## Decision-only evaluation

Run `pnpm run test:jev-decisions` for the offline contracts. After building, `node scripts/jev-decisions-eval.mjs --help` describes the finite command. With `--manifest`, the default is a dry-run: it validates the frozen schema and prints case/input/policy hashes, model, categories, repetitions, maximum attempts, reservations and output paths. It makes no network requests and writes no journal or result files.

Create manifests with `createJevManifest` from `@sutura/evaluation`. The [schema/validator](../../packages/evaluation/src/jev-manifest.ts#L17) fixes the exact controller SHA, public/redacted input and corpus hashes, question versions, requested model `jev-1.14.0`, thresholds, three repetitions, off/assist arms, development/evaluation split and root families. Required questions need independent labels; a navigator's explicitly false/uncertain applicability can omit an inapplicable Choice label. The constructor never invents labels, observed baseline decisions or spend authority. Credentials must already be redacted before freezing/authorization. Development examples and invented metric fixtures cannot qualify live model quality; at least 30 independent evaluation families and positive, negative and uncertain/adversarial variants remain required per role.

Live execution requires all of `--live`, `--manifest`, positive `--max-usd`, and `--authorize-data` equal to the dry-run's manifest SHA-256. It also requires a clean exact executing script checkout and `TYPESAFE_API_KEY`. Those program controls do not replace owner approval during agent use. Only the frozen redacted state/questions are transmitted. Concurrency is one; calls use the shared bounded transport, separate semantic reservations and fixed probability rules. This cap covers Jev decisions, not Nemotron, optional legacy audits, sandbox preparation or full repairs.

The private journal reserves before each actual attempt. Its key includes manifest, arm, case, repetition, role, question version, policy hash, input hash and attempt. Explicit 429/5xx responses may receive one separately reserved retry; unknown transport completion and timeouts are never automatically resent. Native failures remain individual observations, including their missing/unknown cost. Completed observations retain their original latency, cost and offline/live/probe provenance on restart; replaying a mocked response cannot promote it to live evidence.

An interrupted/unknown attempt remains pending and blocks further provider work. Use the visible local reconciliation interface: `--reconcile` identifies the exact attempt; supply a documented `--receipt` and exactly one of `--observed-usd` or `--quarantine`. Quarantine charges the entire reservation. Reconciliation appends the observed disposition and never resets historical spend or resends the key. Preserve both the original journal and billing evidence. The next explicitly authorized invocation can continue other finite attempts after reconciliation.

Results are separate comparison and observation sidecars. They retain every expected case/arm/repetition, error, missing answer, abstention, cost/unknown amount, token usage, latency and per-case failure. Descriptive Wilson intervals use correlated case repetitions and do not establish population safety. Off-arm label observations incur no evaluator Jev request; their zero evaluator cost is not a claim that the original controller/diagnosis was free. Atomic audit v2 retains an explicit original legacy observation alongside experimental evidence; missing legacy evidence remains UNMEASURED. The legacy veto model, request bytes and thresholds remain unchanged.

## Whole-controller comparison

Decision labels/call latency cannot establish avoided sandbox work or verified repair yield. The separate path uses the existing `runBenchmark` and `SuturaAdapter`, fresh fixture roots and unchanged hidden verification. Benchmark adapter semantic options are explicit only; default adapter argv remains unchanged. `withTavily` retains explicit arm configuration.

`BenchmarkOptions.jevComparison` binds one selected case to a frozen descriptor. The harness observes the actual Sutura adapter configuration, generates a fresh invocation UUID and binds it into the native evaluation ID. Core records the actual semantic configuration in case evidence. Import rejects off-as-assist reports, mismatched policy/models/corpus, duplicate invocation/result/billing evidence, changed hidden test identity, and malformed input. Older reports without observed arm metadata remain PARTIAL, even when their historical outcomes are retained.

`node scripts/jev-controller-compare.mjs` supports read-only preparation and retained-result import. Required inputs are `--manifest`, `--proof`, `--source-budget` and `--pricing`; `--runs` supplies the complete retained record array. Optional `--import-report` plus `--measurement` imports an existing observed benchmark and authoritative cost/native-cancellation receipt. Optional `--output` writes a new private file exclusively, preserving input files. A reconciled last partial import is preserved alongside its replacement. It performs no benchmark, provider request, dispatch or new full-run accounting.

The proof references the existing versioned run manifest and dated sandbox-price evidence. Declared inference/sandbox maxima and remaining cumulative/category allocations are checked separately from the Jev cap. **Standalone local full-run admission is currently unsupported/UNMEASURED**: those declarations do not prove that the generated runtime enforces the same full limits. Preparation therefore returns `blocked`, `command: null` and at most a clearly nonexecuting proposed descriptor. No runnable paid command is published. Actual execution requires the existing separately approved paid-run reservation/recovery procedure with enforced full provider/sandbox bounds; this feature does not create a second dispatch/accounting system.

Imported runs retain gave-up and infrastructure-stop outcomes. Missing authoritative USD, unresolved semantic charges or incomplete native cancellation produce PARTIAL and prevent another selected paid run. Raw sandbox metric units are never silently converted to dollars. Explicit complete billing reconciliation can resolve unknown provider charges while preserving the original observation. Both arms must retain exact controller/corpus/model/policy/repair-limit identities; order alternates across repetitions.

Qualification also preserves verified repair yield, rejects newly accepted deceptive patches, additional independently labeled legitimate audit refusals, authority violations and ignored insufficient evidence. Ranking needs the specified 10% sandbox-seconds or cost-per-verified-repair gain with 5% regression limits. Grounding uses relevant recall and top-three precision or **successful-repair cost**, excluding savings on failed runs; mixed-variant costs that cannot be attributed remain unmeasured. Classification/recovery need preserved accuracy/authority and the specified role latency or inference-spend gain. Navigator top-three membership is distinct from top-one correctness and requires usable applicability; every negative query must return no result. Reports never auto-enable a passing role.

The exact criteria and remaining empirical acceptance are in the [approved Phase 2 contract](../plans/2026-10-28-jev-decision-improvements-phases/phase-2.md). Release, production, provider settings and hosted roles retain separate authority.


## Local evidence navigator

The local CLI `explain` command reads one explicitly selected stable regular JSON file, up to 4 MiB, and validates a serializable evidence projection. It supports schema-less native case files and `sutura-case-lab-result-v1` envelopes without depending on Case Lab. It ignores arbitrary trace bodies and file-supplied commands/actions. Recognized identities, numbers, statuses and evidence are validated; missing legacy verification remains unavailable. IDs bind case identity, exact field locator and redacted content, so JSON whitespace does not change them. Output makes controls visible and escapes terminal/HTML/Markdown presentation.

Lexical mode is the default and selects up to three source excerpts without network. Semantic mode is explicitly selected with `--semantic`, an existing key and a positive cap at most USD 0.002. The disclosed payload contains only the redacted query and bounded candidates; it uses one pinned-model request, no retry, and the shared probability/membership policy. It cannot invent paths, commands, actions or causal explanations. Unknown/duplicate choices, low confidence, unexpected model, missing key, cap/deadline and provider failure remain unavailable with labeled lexical fallback. Confident no-match returns no evidence. JSON and text include provenance, exact locators and a fixed next action.

Status/exit pairs are matched/0, no-match/0, unavailable/1 and invalid-input/2. Invalid input returns a correction to select the actual stable regular JSON file or a bounded query. Neither lexical nor semantic navigation replays a run or executes repository code. The existing no-follow/nonblocking reader checks the opened and current file's device, inode, size, mtime/ctime and parent identity before/after reading; replacement, growth, truncation and symlink races fail closed.

The offline golden suite uses 30 constructed, independently field-labeled cases and 30 unrelated queries, with three actual local selector calls per query. It sends actual off-arm labels/resources through the Phase 2 evaluator; absent semantic observations remain UNMEASURED. Constructed cases and correlated repetitions do not establish population accuracy, provider quality or comprehension. Five fixed owner tasks—cause evidence, stopped gate, missing assurance, actual cost and next recovery action—remain a separate usability observation; no owner answers or times have been measured in this implementation run.


## Explicit Action controls and question-contract repairs

The Action accepts `jev-ranking`, `jev-grounding`, `jev-classification` and `jev-recovery` as `off|shadow|assist`, all default off. `jev-budget-usd` defaults to zero and can only lower the shared USD 0.02 maximum. Nonoff modes require an explicit positive cap and `typesafe-api-key`; verify-only mode rejects these healing controls. The pinned semantic client is separate from the unchanged legacy audit client. No input grants execution, verification, source, publication or merge authority.

Shadow captures bounded redacted comparison inputs in a private runner-local file and returns its path as `semantic-shadow-path`. It does not perform inline semantic inference or upload the raw comparison input. Keep the file private when collecting it for an explicitly authorized evaluation.

`navigator-v2` asks one best-evidence Choice and one applicability Noul. A valid semantic match returns at most one original evidence block; lexical mode still returns up to three. The independent optional second/third ranking questions are removed, so uncertainty about an unused rank cannot discard a strong best result. `recovery-v2` similarly selects at most one validator-approved hypothesis; deterministic recovery and the existing generative fallback keep their at-most-two contract. All shared probability thresholds, malformed/uncertain-result fallbacks, deadlines, caps and executable validators stay unchanged.

`ranking-v3` identifies each node by its exact payload index and includes the recorded command and truncation/process metadata. Failure identity follows the failing check, invariant or error mechanism; changed actual values or stack locations alone do not establish progress. A different observed failure does not verify the repair. Known incomplete or abnormal observations retain native order before any provider call or shadow capture. `grounding-v2` separates topical relevance from agreement: a passage about the same package, version and error can be relevant while contradicting the diagnosis. Experimental `atomic-audit-v4` defines test deletion, disabled execution, widened assertion predicates, suppressed application error paths and unrelated changes separately. Predicate changes are distinct from test registration/execution, and ordinary computation repair is distinct from bypassing an existing application error path. It remains evidence-only.

Frozen ranking v1/v2, grounding/navigator/recovery v1 and atomic audit v2/v3 manifests remain readable without rewriting their hashes, questions, labels or historical results. New question versions and exact policy/input hashes distinguish new experiments. Navigator comparisons use actual returned selections (or actual Choice selections when no returned list exists), excluding an explicitly declared `none` sentinel. Unselected probability alternatives do not earn retrieval credit or become unsupported evidence. These repairs do not qualify live model quality or establish a repair-yield improvement.

Before the v2 question-contract repair, a three-call navigator-v1 development probe returned valid typed responses from the exact pinned model. All three decisions were uncertain, so its conditional broader pilot did not run. That historical pin-compatibility observation does not qualify the revised questions, other roles or whole-controller behavior.
